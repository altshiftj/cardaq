# Serial bootstrap checklist

- [x] Inspect the workspace and local RPC precedents. Recorded the empty repository, Windows Python baseline, Timecop layout, and adapter protocol references in the report.
- [x] Write the report, plan, and checklist before implementation.
- [x] Add packaging, virtual environment instructions, TOML settings, and command entry points. Installed with `py -3.12 -m venv .venv` and `.venv/Scripts/python.exe -m pip install -e .` on Windows. `python -m pip check` passed in the virtual environment.
- [x] Implement serial enumeration and read-only adapter identification. Both `cardaq ports` and `python -m cardaq ports` listed COM3 and COM4, matching `python -m serial.tools.list_ports`.
- [x] Document the setup, command usage, RPC convention, and project roadmap in the README and roadmap.
- [x] Verify the CLI and scripted exchanges. `python -m unittest discover -s tests -v` passed four tests on Windows Python 3.12 and Debian Python 3.11 under WSL. On Debian, a pseudo-terminal exchange through `python -m cardaq identify` returned the simulated hardware and firmware IDs. Windows CLI checks confirmed TOML precedence, an empty port list, and exit status 1 for missing or unavailable ports, missing configuration, and invalid timeout.
- [x] Adopt uv for dependency locking and the documented workflow. `uv lock --check`, `uv sync --locked`, and `uv run --locked python -m unittest discover -s tests -v` passed on Windows Python 3.12.7 and in a fresh Debian WSL environment with Python 3.11.2. Windows checks also confirmed `uv run --locked cardaq ports` and `uv run --locked python -m cardaq identify --help`.
- [x] Validate identification on the physical adapter. On 2026-11-23 Eastern time, `uv run --locked cardaq ports` listed the newly connected USB serial endpoint on `COM5`. `uv run --locked cardaq identify --port COM5` returned `OBDLink EX r2.7.1` and `STN2232 v5.10.3` at `115200` baud.
- [x] Confirm live read-only communication with the Civic during the same hookup. A one-off pySerial probe returned two Mode 01 support bitmaps from `0100` (`B63CA813` and `90188003`). The adapter reported `ISO 15765-4 (CAN 29/500)` via `ATDP`. `010C` returned payloads `41 0C 0B B8` and `41 0C 0B E0`, which decode to 750 and 760 rpm. Neither support bitmap advertised standard coolant PID `05`, and a direct `0105` request returned `NO DATA`. [OBD Solutions real-time data reference](https://www.obdsol.com/knowledgebase/obd-software-development/reading-real-time-data/)
