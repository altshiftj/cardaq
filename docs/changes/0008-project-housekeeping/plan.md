# Project housekeeping plan

1. Apply the maintainer's MIT choice to CarDAQ's original work. Identify the adapted OBDb field tables and carry their upstream terms in source and distributions.
2. Give a new contributor a reproducible two-drive viewer demo with synthetic inputs. Document how to record, stop, interpret, and share a capture.
3. Align editor test discovery with unittest. Explain how to change a decoder or derived signal and where to record evidence.
4. Keep disk errors distinguishable from serial disconnects. Exercise the normal CLI and verify that the original CSV schema and viewer series remain compatible.
5. Build the source distribution and wheel, check the licenses and viewer resources, and test installation outside the source tree. Add hosted checks for the minimum supported Python and a current version on Windows and Linux.
